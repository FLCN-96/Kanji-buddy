# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running locally

There is **no build step, no package.json, no test suite, and no linter**. React 18 + Babel-standalone are loaded from a CDN and JSX is transpiled in the browser.

Serve the directory with any static server and open `Home.html`:

    python -m http.server 8000
    # → http://localhost:8000/Home.html

Pushes to `main` deploy to GitHub Pages via `.github/workflows/main.yml` (uploads the repo root as the artifact — there is no build step in CI either).

PNG icons are generated by opening `tools/gen-icons.html` in a browser and downloading each canvas into `icons/`. The SVG sources are checked in; the PNG outputs are not regenerated automatically.

## Architecture

### Multi-page shell, shared globals

Each mode is a standalone HTML page (`Home.html`, `Run.html`, `TimeAttack.html`, `Survival.html`, `StreakGuard.html`, `LeechHunt.html`, `Match.html`, `Decipher.html`, `Trace.html`, `Glyph.html`, `StreakInject.html`, `Mastery.html`, `Settings.html`, `Diagnostics.html`, `Dictionary.html`) that:

1. Loads the shared data-layer scripts in fixed order: `data/rank.js` → `data/db.js` → `data/load-cards.js` → `data/daily.js` → (`data/srs.js` for Run only).
2. Loads React/ReactDOM/Babel from unpkg.
3. Loads the page's `.jsx` components as `type="text/babel"`.
4. Calls `await window.loadCards()` and renders the page's top-level `<XxxApp cards={cards} />` into `#root`.
5. Registers `sw.js`.

The data-layer scripts are plain IIFEs that attach singletons to `window` — `window.DB`, `window.Daily`, `window.Srs`, `window.Rank`, `window.loadCards`. Components consume them off `window` directly; there are no imports.

When adding a new page or component, mirror this pattern: add the file to the page's HTML script tags **and** to the `LOCAL_ASSETS` list in `sw.js` (otherwise it won't be precached or available offline).

### Persistence (`data/db.js`)

IndexedDB database `kanji-buddy-db`, current version **4**, six object stores:

- `user_profile` (single record at `id=1`) — display name, total_xp, streak counters, settings blob.
- `card_states` (keyPath `idx`, indexed by `due_date`) — SM-2 state per card: `interval_days`, `ease_factor`, `reviews`, `lapses`, `due_date`, `last_reviewed`, `lapsed_from_interval`, plus mastery breadcrumbs `first_correct_at` / `first_mature_at` / `days_overdue_at_lapse` (all optional, stamped by `Srs.schedule`).
- `sessions` (autoIncrement) — one row per completed run/challenge. Carries the standard outcome columns plus `hour` (local hour-of-day at save time, auto-set by `DB.saveSession` unless the caller overrides).
- `scores` (autoIncrement, `mode_score` index) — best-of tracking for challenge modes.
- `card_events` (v4, autoIncrement, indexes on `idx` / `mode` / `date`) — per-card evidence log written by **every** mode (Run, TimeAttack, Survival, Match, StreakGuard, LeechHunt, Decipher, StreakInject). Shape: `{ idx, mode, outcome, date, meta? }`. Outcome vocabulary is mode-shaped: Run logs the literal verdict (`miss`/`hard`/`ok`/`easy`), challenge modes log `hit`/`miss`. **This store is evidence, not scheduling** — SM-2 still only reacts to Run via `card_states`. Downstream views can treat a Match hit and a Run "ok" as both being signal without corrupting the SRS schedule. Decipher is special: one event per kanji in the committed word (so word-level wins still produce per-kanji evidence).
- `mode_starts` (v4, autoIncrement, indexes on `mode` / `date`) — mode-entry funnel. One row written by each mode App's mount-effect (`DB.recordModeStart(mode)`). Pairs with `sessions` to compute start-vs-complete rates (`DB.getModeFunnel(days)`).

If you need to add a store or index, bump `DB_VERSION` and extend the `onupgradeneeded` block. Existing user data must survive — only delete stores that are obsolete (the `imported_cards` removal is the existing precedent).

`DB.grantXp(amount)` is the **only** sanctioned way to award XP. It updates `total_xp` and calls `Rank.flagPromotion(prev, total)`, which writes `kb-promotion-pending` to localStorage. `Home.html`'s `App` consumes that key on mount and triggers `RankUpModal`. Modes that award XP must use `grantXp` so promotions fire correctly.

### Daily deck (`data/daily.js`)

`Daily.selectDailyDeck(cards, cardStates, size)` builds the Run deck. Size defaults to `Daily.DECK_SIZE` (5) but is configurable per operator via `user.settings.deckSize` — valid values in `Daily.DECK_SIZES` (`[3, 5, 7, 10]`), resolved through `Daily.resolveDeckSize(user)`. Budgets split ~40% new + 40% due + 20% leech (floor 1 each), with cascade-fill if any bucket is short. A card is a "leech" at `lapses ≥ 3`. Cards are returned augmented with `_bucket` (`'new' | 'due' | 'leech'`) and `_state` (the existing card_state, or null for new). New cards always sort first so the intro/learn phase precedes the quiz.

Home gates the panel as **clear** once `reviewed-today >= resolveDeckSize(user)`, even if the SRS backlog is non-zero — otherwise the ~2000-card "new" pool would refill the panel forever.

`Daily.daySeed()` and `Daily.hotChallengeId()` are deterministic per local day. The "hot" challenge has a two-tier bonus: **gold** (`Daily.HOT_GOLD` = 3×) on the first run of the day, **silver** (`Daily.HOT_SILVER` = 1.5×) on every subsequent run. Modes capture the tier via `Daily.hotTier(modeId)` and the multiplier via `Daily.hotMultiplier(modeId)` *before* writing XP (so the end screen can show what was actually applied), then call `Daily.claimHot(modeId)` **synchronously, before the IDB save chain**. Gating the claim on `saveSession`/`grantXp` resolving would be unsafe: on iOS PWA, the page can suspend or be navigated away before the IDB promise chain finishes, leaving the flag unwritten and every run stuck on gold. The claim is a localStorage `setItem` and is idempotent. Claim status is per local date in localStorage (`kb-hot-claimed:YYYY-MM-DD`). Home reads the tier on mount + on `visibilitychange`/`focus` so the spotlight tile updates after a hot run completes. `Daily.HOT_MULTIPLIER` is kept as a legacy alias for `HOT_GOLD`.

### SRS (`data/srs.js`)

SM-2-derived. Verdict → quality: `miss=1, hard=3, ok=4, easy=5`. Key deviations from textbook SM-2:

- **Hard uses a fixed `×1.2` growth factor** instead of `prev × ease`, so it's actually slower than OK. Classic SM-2 treats hard and ok identically post-graduation, making the button cosmetic.
- **Miss drops ease linearly by 0.20** rather than SM-2's quadratic drop (~0.54 on a single miss). A single slip should not halve a card's growth rate.
- **Mature-card lapse recovery**: on lapse of a card with `interval_days ≥ 21`, the pre-lapse interval is stashed into `lapsed_from_interval`. The first pass after the lapse recovers to `round(lapsed_from_interval × 0.25)` instead of flat-resetting to 1d graduation. Preserves earned progress on stable cards without ignoring the slip.

Lapse path (`q<3`) resets `interval_days=0`, `reviews=0`, increments `lapses`, reschedules `+6h` for same-day relearn, and may set `lapsed_from_interval`. Pass path uses fixed graduation (1d, 6d) for the first two reviews (or the mature-recovery interval on first post-lapse pass), then the growth rules above. Easy adds a 1.3× bonus. Ease floor 1.3. Intervals ≥ 4d are fuzzed by ±~15% (min ±1d). The 1d graduation step is never fuzzed.

`Srs.preview(state, verdict)` returns the prospective next state without writing it (used by UI to label verdict buttons); `Srs.labelInterval(days)` formats an interval as `6h / 1d / 5d / 2mo / 1y`.

Run is the only consumer of `card_states`; challenge modes do not touch SM-2 scheduling. RunApp snapshots each verdict's pre-state into an undo buffer for 3 s so the user can roll back a fat-finger (`U` / `Backspace` / click the chip). The snapshot is cleared on next verdict, on expiry, and **on transition to the end phase** — once the session is saved and XP granted, undo must not roll it back.

`Srs.schedule` also stamps three optional mastery breadcrumbs onto the returned state — `first_correct_at` (first non-miss verdict, sticky), `first_mature_at` (first time `interval_days` crosses 21, sticky), and `days_overdue_at_lapse` (set on each lapse, used to validate whether intervals are calibrated to *this* user). They're read by Home/UI helpers but don't feed back into the schedule itself.

### Adaptive light deleveling (`Srs.delevel`, `Daily.runDelevelSweep`)

A v-next maintenance pass that gently relevels *struggling* cards DOWN — the inverse of a lapse, triggered by a standing pattern rather than a single miss. `Srs.delevel(state, evidence, opts)` is **pure**: it scores a card on three signals — `lapses ≥ 2`, recent cross-mode hit-rate `< 0.5` over `≥ 3` events (from `card_events`, folding Run/challenge/**TRACE** evidence), and `ease_factor` at the floor — and if the score > 0 shaves the interval 15%/point (capped at 50%, never below `minInterval` 4d, never *up*), preserving `ease`/`reviews`/`lapses` and the sticky mastery breadcrumbs so the Mastery wall never visibly regresses. Returns a new state or `null`.

`Daily.runDelevelSweep(cardStates, evidenceMap)` maps `delevel` over all states; `Daily.delevelDoneToday()` / `markDelevelDone()` gate it to once per local day (`kb-delevel-pass:YYYY-MM-DD`, mirrors the hot-claim marker). `App.jsx` runs the sweep on Home mount: bulk-reads the last 21 days of events via `DB.getRecentCardEvents(sinceIso)`, builds the evidence map (success = any non-`miss` outcome), persists changes via `upsertCardState`, and surfaces a one-shot `▸ SRS RECALIBRATED · N cards retuned` banner. Deleveled idxs are pushed to a `kb-delevel-trace-queue` localStorage list that TRACE's `selectTraceDeck` prioritizes, so the motor pattern is re-traced before it's demanded blind again. SM-2 (`schedule`) is unchanged and still Run-only; deleveling only ever *lowers* a schedule.

### Mastery page (`Mastery.html`, `data/mastery.js`)

Dedicated page that surfaces the SRS/event data as a "mastery readout." Loads its own shell (`Mastery.html` → `<Mastery>` orchestrator) and switches between four view components based on `user.settings.masteryView` (also mirrored in `localStorage['kb-tweaks'].masteryView`):

- **MasteryCore** — every kanji rendered as a glyph in JLPT-banded rows; glow class encodes mastery tier (cleared / mature / stable / elite). The wall fills in as cards mature — the page IS the progress.
- **MasteryConstellation** — SVG scatter, x-axis `first_correct_at`, y-axis log-scaled `interval_days`. Recently matured stars pulse. Filter chips per JLPT tier; tap a star to open a detail rail.
- **MasteryInstrument** — instrument-panel HUD: 4 oversized metric tiles, XP-velocity sparkline (last 30 days from `sessions`), maturation calendar heatmap (last 56 days from `first_mature_at`), hours-logged readout, milestone log.
- **MasteryDossier** — RPG-codex stack of per-kanji dossier cards. Filter (all / stable / mature / rising / leech) + sort (recent / mastery / a-z) bars. Each card shows glyph, meaning, JLPT, dates, interval, and a strip of recent cross-mode events fetched from `card_events`.

Compute lives in `data/mastery.js` (`window.Mastery`): `computeMastery`, `getMasteryTier`, `getMasteryRoster`, `getJlptBreakdown`, `getRecentMilestones`, `getMaturationCalendar`, `getXpVelocity`. All four views consume from the same precomputed data the orchestrator builds once on mount.

Tier thresholds — `MATURE_DAYS=21`, `STABLE_DAYS=90`, `ELITE_DAYS=365`. Mature is sticky (driven by `first_mature_at`); stable/elite track current interval and can move down on lapse. The Home `<MasterySummary>` strip (slotted above `<LeechPanel>`) renders 4 cells — `cleared / mature / stable / longest` — and navigates to `Mastery.html` on tap. Add `masteryView` to `TWEAK_DEFAULTS` in **both** `App.jsx` and `Settings.jsx` if those defaults grow.

### Cross-mode evidence log (`card_events`)

The Run-only restriction above applies to **scheduling**. For *evidence*, every mode (including non-Run challenges and Decipher's word commits) writes per-card events to the `card_events` store via `DB.recordCardEvent({ idx, mode, outcome, meta? })`. The outcome vocabulary is mode-shaped — Run uses the literal SRS verdict, challenge modes use `hit`/`miss`. Decipher writes one event per kanji in the committed word, on both correct and wrong commits, so per-kanji hit rates compute symmetrically. Downstream consumers should fold the vocabulary at read time rather than forcing modes to standardise (response timing, axis choice, stage number etc. live in `meta`). Each mode also calls `DB.recordModeStart(mode)` from its mount-effect to feed the `mode_starts` funnel — pair with `sessions` rows via `DB.getModeFunnel(days)` to spot abandonment.

### TRACE — stroke-order muscle memory (`Trace.html`)

The first **production-side** mode (beyond recognition): the operator traces each kanji's KanjiVG strokes in canonical order on a neon 田字格 grid. Files: `Trace.html` shell (loads `run.css` + `timeattack.css` + `trace.css`; data scripts + `data/audio.js`; reuses `TAScreens.jsx`), `components/Trace.jsx` (orchestrator `TraceApp` + `TRTopbar` + `selectTraceDeck` — prefers seen kanji, ramps by stroke count), `components/TracePlay.jsx` (the pointer/SVG tracing surface), `components/TraceScreens.jsx` (`TracePre`/`TraceEnd`, reusing `PreTitle`/`PreTicker`/`PreArm`/`TAReady`), `trace.css`.

`TracePlay` parses `card.svg` into ordered stroke `d` paths via `parseStrokes` (DOM order = stroke order; **count `<path>` elements, never `card.strokes`** which is `0` on ~32% of cards), samples the reference stroke with `getPointAtLength`, and scores the captured pointer stroke with a resampled-pointwise comparison (`trScoreStroke`, the $1-recognizer approach) that **only accepts the next expected stroke** (enforces order) and flags reversed direction. Evidence-only: writes `card_events` (mode `'trace'`, outcome `hit` when traced clean else `miss`; `meta` carries accuracy/retries/assisted), **never** `card_states`. XP is granted **flat** — TRACE is intentionally kept OUT of `Daily.CHALLENGE_ORDER`, so it is never hot (no ×3). Tile lives in `Modes.jsx` `CHALLENGES`; routing via `App.jsx` `routes`. Pedagogy guardrail: the ghost is **static** and the draw-on stroke animation is **opt-in / once** (the HINT button) — stacking animation + colour-coding hurts L2 recognition (PMC9403612). RECALL (blank production) is a planned follow-on; the GLYPH companion (below) ships the quadrant/component side.

### GLYPH — spatial component decomposition (`Glyph.html`)

A quadrant/component drill ("QUADRANT LOCK"): rebuild a kanji by tap-placing its top-level components into the correct region on a 米字格 grid. Files: `Glyph.html` (loads the slim `data/glyph-components.json`, **not** the 4.6 MB geometry), `components/Glyph.jsx` (`GlyphApp` + `GLTopbar` + `selectGlyphDeck`/`glCleanComps`), `components/GlyphPlay.jsx` (the 米字格 grid + tap-zones + tray placement surface), `components/GlyphScreens.jsx`, `glyph.css`. Mechanic: tap a component tile → tap a region; correct locks (cyan glow), wrong flashes danger-red + shake; assemble all components → the kanji reveals → advance. Restricted to the ~1,417 kanji with a clean 2-component left/right or top/bottom split (`glCleanComps`). Evidence-only (`card_events` mode `'glyph'`, `hit` when assembled with zero misplacements), flat XP, off the hot rotation — identical contract to TRACE. Pedagogy: the component/logographeme level dominates orthographic processing, and a radical's spatial position transfers to unseen characters.

### 8-bit audio (`data/audio.js`, `tools/gen_audio.py`)

`window.AudioManager` is a `window.DB`-style IIFE singleton. Audio defaults **ON** (`kb-tweaks.sound = 'full'`, `.volume = 0.8`). UI **SFX play everywhere**; a chiptune **background bed** (`amb_challenge`) plays **only** in the bounded modes whitelisted by `BED_MODES` (time/survival/streak/leech/match/decipher) — never Home/Run/Mastery. iOS: the `AudioContext` is created lazily **inside the first user gesture** (`init()` arms the pointerdown/keydown listener; `unlock()` does the ctx + silent-buffer kick) — never eagerly, or iOS pins it suspended. Each page loads `data/audio.js` and calls `AudioManager.init()` at boot; bounded modes call `unlock()` + `setBedForMode(modeId)` from their **PLAY/ENGAGE handler** (not mount — so the bed starts on the press gesture, iOS-reliable), `tick()/correct()/wrong()` at the hit/miss/commit handlers, and `end('good'|'mid'|'bad')` at the end/debrief screen — which **stops the bed** and plays a dark result stinger (reassuring / unresolved / dreary) instead of letting the loop bleed on. The two timed modes (TimeAttack, Match) call `setPanic(true/false)` when the clock crosses its low-time window, ramping a WaveShaper overdrive + closing lowpass + pitch-sag onto the bed for an "end-of-the-line" warp (`end()` and `setBedForMode()` both reset panic). `App.jsx` plays a first-gesture **boot tone** (`welcome()`, or `levelUp()` if a rank promotion was just consumed) + `milestone()` at the streak-milestone site, fires `ui()` on Home element taps via a guarded `sfx()` dispatcher, and gives the daily-run / overclock / streak-inject buttons distinct `dailyTap()`/`overclockTap()`/`injectTap()` tones; `Settings.jsx` exposes the **AUDIO LAYER** section (`setMode`/`setVolume`, applied live). All calls are guarded (`window.AudioManager && …`) so every page works if audio is absent.

Assets are **Python-synthesized, committed outputs** (mirrors `tools/gen_icons.py`): `tools/gen_audio.py` (pure-stdlib, **32000 Hz mono 16-bit WAV**, dark minor-key "bit-like" synthesis — detuned dual-oscillators, PWM, one-pole lowpass, feedback delay, bit-crush; A-minor / Phrygian-coloured at 75 BPM; seamless loops on the `--kb-beat` 1.8s grid) writes `audio/*.wav`; `tools/convert_audio.py` optionally transcodes to `.ogg`/`.m4a` via ffmpeg (degrades gracefully if ffmpeg is absent — `.wav` are the working assets). `AudioManager` probes `.ogg → .m4a → .wav` per asset. `data/audio.js` + every `audio/*` file are in `sw.js` `LOCAL_ASSETS`; `CACHE_FIRST_RX` includes the audio extensions. **When regenerating audio, run `gen_audio.py` (and `convert_audio.py` if ffmpeg present), commit the outputs, and bump `CACHE`.**

### Kanji geometry precompute (`tools/build-kanji-geometry.py`)

For the planned quadrant/component (GLYPH) mode, `tools/build-kanji-geometry.py` parses every card's KanjiVG `svg` offline (pure-stdlib path-`d` flattener) into `data/kanji-geometry.json` (per-stroke bbox/centroid/start/end/len + 2×2/3×3 quadrant occupancy, plus the top-level component split read from the nested `ns1:element`/`ns1:position`/`ns1:radical`/`ns1:phon` groups; stores both `radKangxi` from `card.rad` and `radVisual` from the SVG) and `data/kanji-components.json` (a `byKanji`/`byComponent` inverse index). Stroke counts come from the `<path>` count, never `card.strokes`. GLYPH ships against a **slim derivative**, NOT this heavy file: `tools/build-glyph-data.py` reduces `kanji-geometry.json` to `data/glyph-components.json` (~115 KiB — only the ~1,417 qualifying kanji as `{ n, components:[{el,pos}] }`), which IS in `LOCAL_ASSETS` and is what `Glyph.html` fetches. The full **~4.6 MB** `kanji-geometry.json` and `kanji-components.json` stay committed but **deliberately unprecached** (kept for future features that need per-stroke geometry; regenerate the slim file via `build-glyph-data.py` if the geometry changes).

### Rank ladder (`data/rank.js`)

30 ranks (`Ⅰ NOVICE` → `ⅩⅩⅩ K̷ANJI.exe`), thresholds 0 → 1,300,000 XP. Five colour tiers: **cyan** (1-7, apprenticeship), **magenta** (8-14, operator), **amber** (15-21, adept/master), **transcend** (22-25, mythic), **void** (26-30, hackery near-impossible). The void tier names carry intentional combining-mark distortion + chromatic-aberration text-shadow + a tiny jitter animation so they read as unstable — the visual treatment is centralised in `home.css` (`@keyframes kb-void-jitter`, plus `.tier-void` rules everywhere existing `.tier-*` rules live: `.kb-progress`, `.kb-progress-ring`, `.variant-xp`, `.ku-modal`, `.kb-pop-ladder-row`).

`Rank.flagPromotion(prev, total)` writes a one-shot localStorage marker; `Rank.consumePromotion()` reads-and-clears it. The thresholds are tuned so finishing N5 lands an operator around rank 7-9 (≈25% of the ladder), N4 → rank 12-14, N3 → rank 17-18 — top void ranks are measured in years of consistent play. Don't tweak them without thinking about how they interact with the per-mode XP balances (`RUN_XP`, `TA_XP_*`, etc., defined at the top of each mode's component) and the gold/silver hot multiplier above. When adding a new rank tier color, add styling for it in **every** `.tier-*` block in `home.css`.

### Cards (`data/cards.json`)

Large (≈6.7 MB) bundled deck. Each card has `idx` (1-based, used as the card_state key), `k` (kanji), `jlpt`, `on`/`kun` readings, `mean`, examples, `svg` (KanjiVG stroke order), `strokes`. The order is roughly frequency / JLPT — `selectDailyDeck` relies on this for stable new-card priority.

### Settings & visual variants

`localStorage['kb-tweaks']` stores `{ scanlines, hero, romaji, masteryView, sound, volume }`. `App.jsx` writes the visual ones to `document.body.dataset.*`, and CSS keys off those data attributes; `sound`/`volume` are owned by `AudioManager` (it reads/writes the same blob). Accent is locked to cyan+magenta brand and density is locked to compact (its tuned values are baked into the base CSS rules) — neither is user-tweakable. The `game` visual variant is the only shipped variant and is hardcoded into the shell className on every page; the previous `calm`/`hud` alternates have been retired from the UI. When adding a tweak, add it to `TWEAK_DEFAULTS` in **both** `App.jsx` and `Settings.jsx`, and in every mode's `TWEAK_DEFAULTS_*`.

### Service worker (`sw.js`)

`kb-v31` cache. Source files (`.jsx`/`.css`/`.html`) use stale-while-revalidate so deploys land on the next visit without bumping the cache version. Heavy assets (`.json`/`.svg`/`.png`/`.woff2`, plus audio `.wav`/`.ogg`/`.m4a`) are cache-first. Bump `CACHE` only when you need to force eviction (e.g. removed assets or changed precache list).

`version.json` is handled network-only by an explicit route — it **must never be cached** or the client-side handshake below breaks.

### Version handshake + update banner (`data/version.js`, `version.json`)

iOS Safari (especially in home-screen PWA mode) can pin stale JS/HTML in its caches long after the SW has refetched fresh bytes, and users have no clean way to clear it. The handshake solves this:

1. `.github/workflows/main.yml` stamps the commit SHA into two places on every deploy: `version.json` at the site root, and the `SERVED_SHA` sentinel inside `data/version.js`.
2. Whatever `version.js` the browser ends up running carries the SHA of the deploy **it** came from — stale or not.
3. On boot and every 5 minutes (plus on `visibilitychange`), `version.js` fetches `./version.json?t=<ts>` with `cache: 'no-store'`. `sw.js` serves that route network-only so the answer is always the currently-live SHA.
4. If `SERVED_SHA !== remote.sha`, the page is stale → banner fires. Clicking it unregisters every SW, deletes every Cache Storage bucket, and `location.replace`s to the current URL with an `?upd=<sha>` cache-buster. IndexedDB and `localStorage` are left untouched — user progress survives.

Locally, `SERVED_SHA === 'dev'` short-circuits the check so the banner never fires during development. If you rename the sentinel, also update the `sed` step and its grep guard in the workflow.

A secondary trigger (`watchSW`) surfaces the banner on SW `updatefound` → `installed` transitions for browsers where that path works reliably (desktop / Android). Either signal firing is enough to notify the user.

**Stuck-cache loop guard (iOS PWA):** `caches.delete()` and SW unregister only clear Cache Storage and the SW registration — the iOS Safari **HTTP cache** (a separate layer) can still hand back stale `data/version.js` bytes after the reload, leaving `SERVED_SHA` unchanged. On Home (a passive page), that re-triggers `performRefresh` → reload → same stale JS → infinite reboot loop, only resolved by the user force-closing the PWA and waiting ~10 min for iOS to evict the entry. `consumeUpdMarker` defends against this: when the URL carries `?upd=<sha7>` after a reload but `SERVED_SHA.slice(0,7)` still doesn't match, it sets the `stuckLoop` flag, which makes `handleMismatch` show an amber "UPDATE PINNED BY iOS CACHE — force-close and reopen" banner instead of auto-reloading.

## Conventions

- All code is written for the browser. There is no Node, no bundler, no transpiler outside Babel-standalone — keep components in plain JSX with `React.useState` / `React.useEffect` (no hook imports).
- Components don't import each other. They attach to `window` via `Object.assign(window, { ... })` at the bottom of the file and reference siblings as bare globals (`<RankUpModal ... />`, `window.Daily.X`).
- Per-mode CSS lives in a single top-level `<mode>.css` file. Shared design tokens are in `design_system/colors_and_type.css`.
- Data attribute hooks: `data-screen-label` on `<main>` for analytics-friendly screen IDs; `data-phase` on shells for phase-scoped CSS.
- `.claude/` is gitignored — it contains host-specific paths and must not be committed.
